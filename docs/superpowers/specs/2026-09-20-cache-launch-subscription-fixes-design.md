# 电源缓存竞态、开机启动异步化与页面订阅收敛设计

## 1. 背景

状态采样已按 Provider 拆分，但仍有三个边界问题：电源状态读取可能在写入或系统通知使缓存失效后重新写入旧结果；开机启动设置虽然把同步调用放到后台队列，却仍通过 `sync` 阻塞主 actor；统一快照在每个 Provider 读取完成后都会发布，即使对应数据没有变化，电源页也会因此收到无关的电池、健康或网络更新。

## 2. 目标

- 防止失效前发起的电源读取在 `await` 返回后重新填入缓存。
- 让写入确认使用明确的未缓存读回路径。
- 让开机启动的 ServiceManagement 调用异步完成，设置页显示处理中并在失败时回滚。
- 对未变化的状态域去重，避免无意义的快照通知。
- 让电源控制页只订阅电池和电源策略状态，不订阅统一快照中的其他高频域。
- 保持网络/电源 30 秒兜底刷新和电源状态 5 秒缓存有效期不变。

## 3. 设计

### 3.1 电源缓存版本

`PowerPolicyProvider` 在同一把锁下维护缓存、缓存时间戳和 `cacheVersion`。开始读取时捕获当前版本；读取返回后只有版本仍相同才写入缓存。通知、写入、helper 授权和注销操作都清空缓存并递增版本号，因此任何跨越这些操作的旧读取都不能污染后续缓存。

控制接口增加语义明确的 `readPowerModeUncached(scope:)`，默认实现复用已有单 scope 读取；`PowerPolicyProvider` 直接向 helper 发起未缓存读回，`ControlCoordinator` 在写入完成后使用该接口确认。

### 3.2 开机启动异步化

`LaunchAtLoginManaging.setEnabled` 保持主 actor 调用边界但改为 `async throws`。系统实现通过串行 utility 队列异步执行 `SMAppService` 的状态检查、注册和注销，使用 throwing continuation 等待队列任务完成，不在主 actor 上同步等待。

`PreferencesStore` 不再通过属性 `didSet` 同步变更开机启动。新增异步设置方法和处理中状态：先在主 actor 上乐观更新 UI，异步调用 manager；成功后写入 UserDefaults，失败时恢复旧值。初始化时对已保存的启用状态启动异步同步任务。设置页使用自定义 Binding，处理中禁用开关并显示进度提示。

### 3.3 去重与域状态对象

`SystemStatusStore.rebuildSnapshot()` 比较电池、网络、健康和电源策略四个内容域；只有至少一个域变化时才生成新 `lastUpdated` 并发布快照。

Store 持有稳定的电池、网络、健康、电源策略及更新时间状态对象。统一快照继续作为控制层和菜单栏图标的兼容入口；根状态页继续订阅统一快照。电源控制页改为通过 `ObservedObject` 订阅电池状态和电源策略状态，因此健康、网络采样不会触发其状态依赖。

## 4. 错误处理

- ServiceManagement 异步调用抛错时，设置页恢复之前的开关值，并保持持久化值不变。
- 旧电源读取仍可把旧结果返回给发起它的调用者，但不能写入已失效缓存；后续刷新必须重新访问 helper。
- 状态域去重不改变 Provider 返回的不可用状态语义；只有内容相同的重复结果被忽略。

- 验证控制层使用未缓存读回接口。
- 调整开机启动失败测试为异步调用，并验证处理中期间的状态。
