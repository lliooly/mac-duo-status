# 彩色图标仅作用于电池设计

## 背景

当前组合图标把 `usesColor` 同时传给电池、Wi‑Fi 和系统健康点，并根据该设置切换整张 `NSImage` 的 template 模式。因此打开“彩色图标”后，网络图标和健康点也可能显示蓝色、橙色或红色。

## 目标

- 彩色图标设置只影响电池进度弧线。
- 电池正常状态保持白色。
- 电池由电源适配器供电时显示绿色。
- 电池处于低电量模式且未由适配器供电时显示黄色。
- 未由适配器供电、未开启低电量模式且电量低于 20% 时显示红色。
- Wi‑Fi 图标和系统健康点始终显示白色。
- 彩色设置关闭时，整个组合图标保持白色。

## 方案

### 渲染策略

`StatusIconRenderer` 始终以非 template 图像绘制，避免 macOS 对整张图像统一着色，导致电池的局部颜色丢失或其他区域随设置变化。

绘制组合图标时：

- `drawBattery` 继续接收 `usesColor`，由电池颜色解析逻辑决定进度弧线颜色。
- `drawNetwork` 不再根据 `usesColor` 选择颜色，始终使用白色。
- `drawHealth` 不再根据 `usesColor` 或热状态选择颜色，活动点和非活动点都使用白色，仅保留现有透明度差异来表达点是否填充/可用。
- 电池底层轨道继续使用白色透明度，不因彩色开关改变。

电池颜色优先级固定为：适配器供电绿色 > 低电量模式黄色 > 电池电量低于 20% 红色 > 白色。只有在 `usesColor == true` 时才启用前三种彩色分支；否则电池进度也使用白色。

### 数据流

设置页和弹出面板仍通过同一个 `PreferencesStore.usesColor` 驱动 `CombinedStatusIcon`。不新增配置项，不改变设置持久化键，也不修改电池、网络或健康 Provider。

## 错误处理

- 电池电量、供电来源或健康数据不可用时，沿用现有中性/透明度表现。
- 无论网络类型、网络不可用状态或热状态如何，Wi‑Fi 图标和健康点不使用彩色状态语义。
- 不引入新的回退颜色或新的系统状态。

## 测试

增加纯逻辑测试覆盖电池颜色优先级和开关行为：

1. 彩色关闭时所有电池状态返回白色。
2. 彩色开启时，适配器供电返回绿色。
3. 彩色开启且低电量模式开启时返回黄色。
4. 彩色开启、未接入适配器、未开启低电量模式且电量低于 20% 时返回红色。
5. 其他电池状态返回白色。

同时通过构建和现有测试，确认 Wi‑Fi 与健康点的渲染签名/调用不再读取彩色设置，并且现有设置持久化及状态快照行为不受影响。

## 范围外

- 不改变“彩色图标”设置的名称、位置、持久化方式或默认值。
- 不修改电池颜色阈值、健康分数算法或网络信号级别算法。
- 不实现分层 template 图标或菜单栏前景色自适应方案。
