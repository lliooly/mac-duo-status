# 菜单栏状态面板自适应尺寸设计

## 1. 背景与目标

点击菜单栏图标后，`MenuBarExtra` 的窗口样式当前可能把 `StatusPopoverView` 压缩成只有一条横向内容的细条。原因是面板根部使用了垂直 `ScrollView`，而 `ScrollView` 本身没有可用于菜单栏窗口尺寸推断的固有高度。

本次修复的目标是让状态面板按照实际内容自适应展开，而不是细条或固定高度；同时保留当前的折叠区域和状态内容。

## 2. 已确认的范围

- 修改对象限定为 `StatusPopoverView` 的外层布局结构。
- 不为面板设置固定宽度或固定高度。
- 面板尺寸由当前可见内容和内边距自然决定。
- 区块展开或折叠时，面板高度随内容同步变化。
- 不修改 `SystemStatusStore`、状态模型、菜单栏组合图标或区块内容。
- 不新增用户配置项，也不改变弹出面板中各区域的默认展开状态。

## 3. 设计方案

### 面板布局

移除根部的垂直 `ScrollView`，让包含摘要、分隔线和三个状态区域的 `VStack` 直接成为面板内容。对该内容使用垂直方向的 `fixedSize`，明确告诉 `MenuBarExtra` 根据内容计算固有高度；不使用固定宽高约束。

内容结构保持不变：内边距、摘要区域、分隔线以及 Battery、Network、System Health 三个 `StatusSectionView` 按当前顺序显示。

### 数据流与职责

面板仍从环境中的 `PreferencesStore` 和 `SystemStatusStore` 读取数据。尺寸修复只影响 SwiftUI 布局，不改变状态刷新、偏好写入或区块展开绑定。

### 超出与异常处理

- 不通过固定视口或裁剪内容来解决尺寸问题，所有当前可见内容都参与固有尺寸计算。
- 当某个 Provider 数据不可用时，继续使用现有的 `UnavailableStatusView` 降级展示。
- 如果未来增加大量内容或需要适配极大辅助功能字体，再单独引入基于屏幕可用高度的滚动保护；本次不扩大范围。

## 4. 验收标准

1. 点击菜单栏图标后，面板不再收缩为细条。
2. 面板宽度和高度由当前内容自然计算，不存在固定 `frame(width:height:)`。
3. 展开或折叠任一区块时，面板高度随内容变化。
4. 面板内现有状态摘要和三个状态区域仍可正常显示。
5. 工程能够通过 macOS 目标的构建；现有测试不因本次布局改动失败。

## 5. 验证计划

- 使用 `xcodebuild` 构建 macOS scheme。
- 运行现有单元测试和 UI 测试（若当前环境提供可用的 macOS 模拟/测试目标）。
- 复查变更范围，确保只包含面板尺寸修复及必要的布局注释/测试调整。
