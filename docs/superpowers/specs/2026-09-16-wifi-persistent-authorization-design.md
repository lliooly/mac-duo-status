# Wi-Fi 一次授权持久复用设计

日期：2026-09-16

## 1. 背景

Duo Status 已经能够读取 macOS Wi-Fi 钥匙串中的个人网络密码，以及企业网络的 802.1X 用户名、密码和证书身份。已知网络通常可以直接复用这些系统凭据连接，但如果产品要求连接前验证当前用户，不能让用户每次重复填写 Wi-Fi 账号和密码，也不能让应用自己收集 Mac 登录密码。

本次设计增加一次性的系统身份授权：用户首次通过 Touch ID、Apple Watch 或 Mac 登录密码完成授权后，应用持久化一个不包含凭据的授权标记。之后已知网络切换直接复用 macOS Wi-Fi 凭据，直到用户主动撤销授权。

## 2. 目标与非目标

### 2.1 目标

- 已知网络首次连接前，使用 macOS `LocalAuthentication` 系统界面验证当前用户。
- 认证优先使用 Touch ID；系统会在必要时提供 Apple Watch 或 Mac 登录密码 fallback。
- 认证成功后持久化应用级 Wi-Fi 授权标记，应用重启后继续有效。
- 后续已知网络连接不再重复弹出认证界面，由已授权的特权 helper 复用 macOS 的保存配置。
- 提供“撤销 Wi-Fi 授权”操作；撤销后下一次已知网络连接重新验证。
- 应用永远不接收、保存或记录 Mac 登录密码、指纹数据或 Touch ID 原始信息。
- 保留当前个人网络、WEP 和企业网络的系统凭据读取及手动回退流程。

### 2.2 非目标

- 不修改 Apple 管理的 Wi-Fi 钥匙串条目的 ACL。
- 不创建一个自定义 Mac 登录密码输入框。
- 不让 Touch ID 替代未知 Wi-Fi 的实际网络密码或企业 802.1X 凭据。
- 不把 Wi-Fi 密码复制到 `UserDefaults`、应用授权标记、状态快照或日志。
- 不改变 Wi-Fi 扫描、隐藏网络、网络分组和设置跳转逻辑。

## 3. 设计

### 3.1 授权范围

授权是当前 macOS 用户下 Duo Status 的应用级信任，不按 SSID 单独授权。授权默认一直有效，直到发生以下任一情况：

- 用户在 Duo Status 设置中主动撤销；
- 应用删除或重建了授权标记；
- 当前用户的钥匙串被重置或不可用；
- 应用版本主动提升授权标记版本并要求重新授权。

授权标记只表达“用户允许 Duo Status 发起已知 Wi-Fi 连接”，不包含任何 Wi-Fi 密码、账号或证书内容。它写入应用自己的钥匙串，而不是 `UserDefaults`。

### 3.2 首次授权流程

```text
点击已知网络
  ├─ 已存在应用授权标记
  │    └─ 特权 helper 使用 macOS 保存配置连接
  └─ 没有应用授权标记
       └─ LocalAuthentication 系统认证
            ├─ 成功 → 写入授权标记 → 特权 helper 使用系统保存配置连接
            └─ 取消/失败 → 不连接并展示可恢复错误
```

使用 `LAPolicy.deviceOwnerAuthentication`，由系统决定使用 Touch ID、Apple Watch 或用户密码。应用只接收认证成功或失败结果。不能使用 `deviceOwnerAuthenticationWithBiometrics` 作为唯一策略，否则没有 Touch ID 时无法按用户要求回退到 Mac 登录密码。

### 3.3 后续连接

`ControlCoordinator` 在发起已知网络连接前调用授权服务：

- 授权标记存在时直接返回成功，不显示 UI；
- 授权标记不存在时调用 `LAContext.evaluatePolicy`；
- 认证成功后写入标记，再由 `CoreWLANNetworkController` 通过 XPC 调用已授权的特权 helper；
- helper 优先调用 `networksetup` 让 macOS 使用保存的网络配置；必要时在 helper 内读取系统 Wi-Fi/EAP 钥匙串并完成 CoreWLAN 连接；
- helper 只返回连接结果，不把 Wi-Fi 密码或企业凭据返回主 App；保存配置不可用时，主 App 回退到现有手动凭据页。

未知网络仍然需要用户提供真实 Wi-Fi 密码。用户选择记住网络后，凭据写入 macOS Wi-Fi 钥匙串，后续该网络会按照已知网络路径处理。

### 3.4 授权存储

增加独立的授权边界，例如：

- `WiFiAuthorizationProviding`：执行系统身份认证和读取/写入授权状态；
- `LocalAuthenticationWiFiAuthorizer`：封装 `LAContext`，不向 UI 暴露登录密码；
- `WiFiAuthorizationStore`：以固定 service、account 和版本写入应用钥匙串中的非敏感标记。

授权标记读取失败时按“未授权”处理并重新请求系统认证。写入失败时不继续执行需要授权的连接，避免 UI 显示已授权但下一次状态丢失。

### 3.5 撤销

设置页增加“撤销 Wi-Fi 授权”操作。撤销只删除应用自己的授权标记，不删除 macOS Wi-Fi 配置或 Wi-Fi 密码。成功删除后，下次连接已知网络时重新弹出系统认证。

## 4. 错误处理

| 场景 | 处理 |
| --- | --- |
| 首次认证成功 | 写入授权标记并继续连接 |
| 用户取消 Touch ID/密码认证 | 不连接，保留网络列表 |
| Touch ID 不可用 | 系统认证界面回退到 Apple Watch 或 Mac 登录密码 |
| 授权标记读取失败 | 按未授权处理并重新认证 |
| 授权标记写入失败 | 不执行需要持久授权的连接，显示授权失败 |
| 已授权但 Wi-Fi 密码不存在 | 进入现有网络密码页 |
| 已授权但 Wi-Fi 密码过期 | 显示认证失败，允许输入新的网络密码 |
| 未知网络 | 仍要求实际 Wi-Fi 密码；Touch ID 不能替代它 |
| 特权 helper 未安装或未批准 | 提示启用一次高级 helper，不展示伪造的 Wi-Fi 密码输入 |
| 撤销授权 | 只删除应用标记，不删除系统网络配置 |

## 5. 测试计划

### 5.1 逻辑测试

- 没有授权标记时只触发一次授权服务调用。
- 已有授权标记时连接不会重复调用授权服务。
- 授权成功后标记写入，应用重新创建后仍可读取。
- 撤销后标记消失，下一次连接重新要求授权。
- 授权服务失败时不调用网络连接层。
- Wi-Fi 密码和企业凭据不会出现在授权标记或 `UserDefaults`。

### 5.2 平台与 UI 验证

- 在有 Touch ID 的 Mac 上验证首次授权显示系统认证界面。
- 验证选择密码 fallback 可以完成授权，应用不接收密码内容。
- 验证重启应用后已知网络可直接切换，不重复授权。
- 验证特权 helper 批准后，已知网络连接不弹出 System keychain 管理员对话框。
- 验证撤销后再次连接会重新请求授权。
- 验证未知网络仍显示真实网络密码输入页，已知网络缺少凭据时正确回退。
- 运行现有 Wi-Fi 扫描、连接、钥匙串回退和菜单栏 UI 测试。
