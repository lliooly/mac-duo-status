# Wi-Fi 原生凭据连接修复设计

日期：2026-09-15

## 1. 背景

Wi-Fi 控制页已经可以扫描网络、区分已知网络和其他网络，并支持隐藏网络入口。但当前连接交互有两个问题：

1. 点击网络后，密码页通过 `.sheet` 从菜单栏窗口弹出，输入框可以显示但无法稳定获得键盘焦点。
2. 已知网络只被用于分组，连接时仍然把凭据作为空值传给 CoreWLAN，不能像 macOS 原生 Wi-Fi 页面一样复用系统已经保存的密码。

本次修复将连接行为调整为原生 Wi-Fi 的凭据策略，同时保留此前已经完成的扫描、隐藏网络和设置页修复。

## 2. 目标与非目标

### 2.1 目标

- 已知网络点击后优先使用 macOS Wi-Fi 钥匙串中已有的凭据直接连接。
- 已知网络没有可用凭据时，回退到密码输入页面。
- 未知的受保护网络显示密码输入页面，输入框自动获得焦点。
- 真正的开放网络不要求密码。
- 用户在手动输入密码后勾选“记住此网络”时，将凭据写入 macOS Wi-Fi 钥匙串并保存网络配置。
- 不让密码进入 `UserDefaults`、日志或值类型状态快照。
- 去掉从菜单栏窗口弹出的凭据 `.sheet`，避免 AppKit 激活事件错配和键盘焦点丢失。
- 保护个人、WEP 和企业网络的凭据路径，已知企业网络优先复用系统 EAP 凭据和证书身份。

### 2.2 非目标

- 不扫描任意钥匙串条目，也不实现第三方密码管理器集成。
- 不自动连接用户没有点击的网络。
- 不改变网络扫描分组、隐藏网络定向扫描和 Wi-Fi 设置跳转的既定行为。
- 不把密码复制到 UI 之外的持久化模型。

## 3. 当前问题与根因

### 3.1 密码页焦点不稳定

`WiFiControlView` 使用 `.sheet(item:)` 展示 `WiFiCredentialView`。应用采用 `MenuBarExtra` 的窗口样式，密码页在菜单栏窗口激活状态变化时可能失去键盘焦点，并产生 `Stale deferred activation` 日志。当前页面没有显式的 `FocusState`，因此用户看到密码框也无法输入。

### 3.2 已知网络没有复用系统凭据

`CoreWLANNetworkController` 从 `CWNetworkProfile` 读取安全类型和 SSID，只将结果标记为 `isKnown`。连接时却总是调用 `associate(to:password:)`，凭据为空时传入 `nil`。CoreWLAN 的个人网络关联接口需要 WPA/WPA2/WPA3 或 WEP 密码；已知状态本身不会自动把钥匙串密码注入这个调用。

CoreWLAN 提供 `CWKeychainFindWiFiPassword`、`CWKeychainFindWiFiEAPUsernameAndPassword` 和 EAP 身份读取接口，可以按 SSID 从用户或系统 Wi-Fi 钥匙串取回原生网络凭据。连接层应使用这些官方接口，而不是执行 `security` 或 `networksetup` 命令。

## 4. 设计

### 4.1 连接决策

连接前根据候选网络和凭据来源选择路径：

```text
点击网络
  ├─ 已知网络
  │    ├─ 开放网络 → 直接关联
  │    ├─ 个人/WEP → 读取用户/系统 Wi-Fi 钥匙串 → 直接关联
  │    └─ 企业网络 → 读取 EAP 用户名、密码、证书身份 → 直接关联
  │         └─ 读取不到 → 进入密码页
  └─ 未知网络
       ├─ 开放网络 → 直接关联
       └─ 受保护网络 → 进入密码页
```

“已知”只表示 macOS 存在对应的网络配置，不会把受保护网络误判成开放网络。真正的开放网络仍然可以无密码连接，因为协议本身没有密码。

### 4.2 钥匙串凭据桥接

在平台层增加小型 Wi-Fi 凭据访问边界，调用 CoreWLAN 官方钥匙串函数：

- 读取时依次尝试用户域和系统域；只返回临时内存中的凭据。
- 个人/WEP 网络使用 SSID 查找网络密码。
- 企业网络使用 SSID 查找 EAP 用户名和密码，并读取关联的 `SecIdentity`。
- 写入时只在用户勾选“记住此网络”后执行，优先写入用户域；写入失败不回滚已经成功的连接，返回“已连接但未记住”。
- 不记录凭据内容和 SSID 密码查询结果到日志。

`CoreWLANNetworkController` 的 `associate` 接收候选网络的 `isKnown` 信息：

- 已知网络且调用方没有提供手动凭据时，先从钥匙串补全凭据。
- 受保护网络最终没有凭据时返回新的 `credentialsRequired` 错误。
- 未知网络的手动密码仍由 `WiFiCredentialView` 传入。

### 4.3 凭据页面与焦点

`WiFiControlView` 不再使用 `.sheet(item:)`。页面状态改为网络列表和凭据页二选一：

- 未知受保护网络点击后，直接在当前菜单栏窗口内显示 `WiFiCredentialView`。
- 凭据页提供返回按钮，取消时回到网络列表。
- `WiFiCredentialView` 用 `@FocusState` 管理用户名和密码输入框，并在页面出现后自动聚焦第一个需要填写的字段。
- 多 BSSID 网络先保留现有接入点选择，再进入凭据页或执行已知网络直连。
- 已知网络点击后先执行无 UI 的原生凭据连接；如果返回 `credentialsRequired` 或钥匙串认证失败，再切换到凭据页。

`ControlCoordinator.connect` 返回结构化连接结果或错误，让 UI 能区分“连接失败”和“需要用户输入凭据”，而不是通过共享状态猜测页面跳转。

### 4.4 记住网络

未知网络手动连接成功后：

- “记住此网络”关闭：不写入钥匙串和配置文件。
- “记住此网络”开启：将对应个人/WEP 或企业凭据写入 CoreWLAN Wi-Fi 钥匙串，再提交 `CWNetworkProfile`。
- 任一记住步骤失败时，连接保持成功，但结果标记为未记住并显示已有提示。

已知网络直连不重复写入配置，避免普通点击改变系统网络优先级或凭据。

## 5. 错误处理

| 场景 | 处理 |
| --- | --- |
| 已知网络存在系统密码 | 直接使用钥匙串密码连接 |
| 已知网络没有可读取密码 | 返回 `credentialsRequired`，进入密码页 |
| 未知个人/WEP 网络 | 显示密码框，密码为空时禁用连接 |
| 企业网络 | 优先使用 EAP 用户名、密码和证书身份；缺失时进入企业凭据页 |
| 开放网络 | 不显示密码框，直接连接 |
| 钥匙串读取被拒绝 | 不记录密码，回退到手动输入 |
| 输入框失去焦点 | 由内嵌凭据页和 `FocusState` 自动恢复焦点 |
| 连接成功但记住失败 | 保持连接成功，显示“已连接但未能记住” |

## 6. 测试计划

### 6.1 纯逻辑测试

- 已知开放网络选择无凭据直连路径。
- 已知受保护网络选择系统凭据路径，不要求 UI 输入。
- 未知受保护网络选择手动凭据路径。
- 钥匙串没有凭据时返回 `credentialsRequired`，不把网络当成开放网络。
- 手动密码和“记住网络”状态正确传递，密码不进入快照或 `UserDefaults`。

### 6.2 平台与 UI 验证

- 构建并签名检查 Wi-Fi 定位权限配置。
- 在真实 macOS Wi-Fi 接口上验证已知网络的用户域/系统域凭据读取不输出密码内容。
- 验证未知网络凭据页可获得键盘焦点，连接按钮和错误状态正常工作。
- 保留并运行已有扫描合并、隐藏网络、同 SSID 多接入点和设置跳转测试。
