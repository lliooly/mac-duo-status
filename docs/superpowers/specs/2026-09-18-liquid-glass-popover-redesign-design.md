# Duo Status 下拉面板 Liquid Glass 重设计

## 目标

按照已选定的参考图重新设计菜单栏下拉面板，并将同一视觉语言延伸到电源控制与 Wi‑Fi 控制二级页面。此次变更只调整 SwiftUI 前端，不修改 Provider、Domain、Helper、协议、系统命令或状态管理的数据语义。

成功标准：

- 根页面在浅色与深色外观下均具有参考图中的紧凑卡片层级。
- macOS 26 及以上仅在面板最外层使用苹果官方最通透的 Liquid Glass：`.glassEffect(.clear, in:)`。
- 卡片本身不叠加 Liquid Glass，避免多层玻璃造成视觉噪声和性能浪费。
- macOS 26 以下继续使用现有原生材质降级方案。
- 现有电池、能源模式、Wi‑Fi、系统健康、设置、退出、授权和错误处理能力全部保留且可访问。
- 根页面、二级页面和指标切换具有克制、连贯且支持“减少动态效果”的动效。

## 范围

### 包含

- `StatusPopoverView` 根页面的布局、层级、样式与页面切换方式。
- `PowerControlView` 和 `WiFiControlView` 的视觉统一。
- 电池、Wi‑Fi、系统健康摘要卡片。
- 页面切换、卡片入场、进度变化、指标切换等前端动效。
- `DuoStatusStyle` 中与颜色、间距、圆角、描边和动画相关的共享视觉常量。
- 必要的 SwiftUI 展示组件拆分和 UI 测试标识维护。

### 不包含

- 后端命令、XPC Helper、权限模型、状态采集频率和业务规则调整。
- 新的数据源、持久化能力或设置项。
- 修改菜单栏状态图标本身。
- 使用自定义玻璃实现替代苹果官方 `glassEffect`。

## 视觉方向

采用“高还原摘要式”布局。根页面不再使用三组折叠面板，而是固定展示三张摘要卡，使信息层级与参考图保持一致。详细数据和操作仍通过二级页面或现有控制入口访问，因此减少首页噪声但不移除功能。

### 外层面板

- 维持适合菜单栏弹窗的固定宽度，结合内容重新校准内部留白和垂直节奏。
- macOS 26 及以上使用 `.glassEffect(.clear, in: RoundedRectangle(...))`，并保留连续圆角裁切。
- macOS 26 以下使用 `.ultraThinMaterial` 或现有等价原生材质作为降级背景。
- 外层可保留轻微描边与系统阴影，颜色随浅色、深色模式自适应。
- 不在外层之外增加模拟玻璃的渐变、模糊层或自绘光泽。

### 卡片

- 三张卡片使用统一连续圆角、细描边和轻量半透明系统色背景。
- 卡片不调用 `glassEffect`，避免与外层 Liquid Glass 重叠。
- 颜色以系统前景色、次要前景色、系统绿色与应用强调蓝为主。
- 文本使用系统字体，标题、主要数值、辅助描述形成清晰的三级层级。

## 根页面结构

### 顶部标题栏

- 左侧显示 `Duo Status` 与最近更新时间。
- 右侧使用现有设置入口，呈现为图标按钮并保留可访问性标签。
- 移除当前顶部的大尺寸组合状态图标，使标题区更接近参考图并为内容释放空间。

### 电池摘要卡

- 首行显示系统电池图标、标题和右侧大号电量百分比。
- 中部显示可动画更新的电量进度条。
- 底部显示供电来源与当前能源模式的简短组合说明。
- 右侧保留进入电源控制二级页的明确入口。
- 电池缺失或不可用时，沿用现有不可用语义，以占位说明替代百分比与进度，而不是伪造数值。

### Wi‑Fi 摘要卡

- 显示系统 Wi‑Fi 图标、标题与信号强度表达。
- 突出当前 SSID，并在下方显示连接状态。
- 提供进入 Wi‑Fi 控制二级页的入口。
- 未授权、未连接或不可用状态继续使用现有状态数据和文案，不新增后端分支。

### 系统健康卡

- 顶部显示系统健康图标与标题。
- 使用现有 `HealthMetricSelector` 对 CPU、温度、负载进行分段切换。
- 下方展示当前指标的大号数值、说明文本和状态点。
- 切换只改变当前展示指标，不改变数据采集或健康评分逻辑。

### 底部操作

- 根页面底部保留退出操作，并采用接近参考图的轻量图标文字样式。
- 设置入口集中到标题栏，不在底部重复出现。

## 二级页面

`PowerControlView` 与 `WiFiControlView` 使用同一页面骨架：

- 顶部为返回按钮、页面标题和可选的状态说明。
- 内容按职责分成与根页面一致的非玻璃卡片。
- 现有按钮、选择器、授权提示、系统设置跳转、错误提示和加载状态全部保留。
- 不改动 `ControlCoordinator` 的调用方式，也不改变操作成功或失败后的刷新行为。
- 二级页面的内容高度继续由 SwiftUI 自适应，避免强行压缩现有控制项。

## 组件边界

- `StatusPopoverView`：负责根页面与二级页面路由、外层 Liquid Glass 容器和共享页面过渡。
- 摘要卡组件：只接收已格式化或可直接展示的状态值，负责布局和交互入口，不读取后端。
- `DuoStatusStyle`：集中保存共享颜色、圆角、描边、阴影、间距和动画参数。
- `HealthMetricSelector`：保留现有选择绑定，调整为参考图中的分段控件样式。
- `PowerControlView`、`WiFiControlView`：保留业务行为，仅替换页面骨架和展示样式。

若拆分新组件，应按单一职责组织，不把业务判断从现有 Store 或 Coordinator 复制到纯展示组件中。

## 数据流

1. `SystemStatusStore` 继续生成 `SystemStatusSnapshot`。
2. `StatusPopoverView` 和二级页读取现有环境对象。
3. 根页面将快照中的电池、网络和健康状态映射为摘要卡展示值。
4. 用户进入二级页后，现有控件继续通过 `ControlCoordinator` 发起操作。
5. 操作完成后沿用现有刷新机制更新 `SystemStatusStore`，SwiftUI 重新渲染并驱动轻量数值动画。

前端不得新增绕过 Store 或 Coordinator 的系统调用。

## 动效

- 根页面进入二级页：短距离横向位移配合淡入淡出；返回时方向相反。
- 卡片入场：依次进行轻微上浮和透明度变化，总时长保持克制，不制造明显等待。
- 电量进度和健康指标：状态变化时使用约 0.2 秒的系统缓动。
- 分段选择：选中背景和内容变化使用轻量弹簧或等价原生动画。
- 按钮：使用系统 hover、pressed 与 focus 反馈，不加入装饰性循环动画。
- 当环境启用“减少动态效果”时，移除位移和弹簧，仅保留必要的瞬时或淡入淡出状态变化。

所有动效仅包裹 UI 状态变化，不延迟或改变后端操作。

## 错误与边界状态

- 保留现有授权不足、Helper 不可用、网络未连接、电池不存在、指标不可用和操作失败文案。
- 摘要卡不能展示有效数据时，显示本地化的不可用状态，不显示误导性的 `0`。
- 长 SSID、长本地化文案和窄面板空间采用合理截断、换行或缩放策略，不扩大到不可控宽度。
- 动态更新期间避免重置用户当前所在二级页面或当前选中的健康指标。

## 兼容性与可访问性

- macOS 26 及以上使用官方 Liquid Glass `.clear` 档位。
- 旧系统保留原生 Material 降级路径，功能和内容与 macOS 26 一致。
- 保留或更新现有 accessibility identifier，确保 UI 测试仍能定位设置、退出、状态卡、指标选择和二级页入口。
- 图标按钮提供明确的辅助功能名称；颜色不是唯一的状态表达方式。
- 支持浅色、深色、高对比度和减少动态效果设置。

## 验证计划

- 编译应用并运行现有单元测试与 UI 测试。
- 验证根页面到电源、Wi‑Fi 二级页的进入与返回。
- 验证设置、退出、能源模式控制、Wi‑Fi 控制及授权入口仍调用现有行为。
- 对照参考图检查浅色和深色外观下的间距、圆角、层级、字号与卡片密度。
- 在 macOS 26 检查外层 `.glassEffect(.clear)`，并确认卡片未叠加 Liquid Glass。
- 检查旧版 macOS 的编译分支与材质降级。
- 检查中文、英文、长 SSID、不可用状态、减少动态效果和辅助功能标识。

## 实现边界检查

- 不新增或修改后端接口。
- 不更改现有状态模型含义。
- 不删除功能，只重新分配根页面摘要与二级页面详情的信息层级。
- 不创建 worktree。
- 不引入第三方 UI 框架或自定义玻璃渲染。
