# Duo Status 合并控制版本测试说明

## 1. 测试目标

测试重点不是覆盖所有 macOS 设备，而是确保基础状态和合并控制版本在支持范围内：

- 状态读取结果可信。
- 组合图标、弹出面板和设置面板使用同一份状态。
- 状态暂不可用时不会显示误导性旧数据。
- CPU 和负载的图标变化经过平滑处理。
- 不支持、需要授权或暂不可用的能力不会显示为可用按钮。
- 控制操作不会乐观更新，必须在真实读回确认后才显示成功。
- Wi-Fi 凭据不落盘；电源辅助进程不可用时仍能使用只读状态。

## 2. 测试层级

### 2.1 纯逻辑测试

不依赖真实 Mac 状态，覆盖：

- 电量百分比计算和 0% 至 100% 限制。
- 电池颜色优先级。
- Wi-Fi RSSI 到信号级别的映射。
- 网络类型对应的图标和是否显示 RSSI。
- CPU 健康分数。
- 系统负载健康分数。
- 热状态到健康分数的映射。
- 健康分数到 0 至 4 个点的四舍五入。
- 平滑处理。
- 无效值和暂不可用值。
- Wi-Fi 网络按 SSID 合并、按信号选择 BSSID，并按安全族选择连接策略。
- 充电上限 80–100 的范围校验和能力状态映射。
- `pmset` 能源模式的 0/1/2 映射、`powermode`/`lowpowermode` 解析和 Battery/AC 区块解析。
- 能源模式输出缺失、重复、未知值或非整数时降级；只有 Low Power 能力时不暴露 High Power。
- helper 无法读回且公开 Low Power 为 false 时，不把状态映射为 Automatic。
- 控制操作状态从 pending 到 succeeded/failed 的转换。

健康分数边界处理和平滑算法尚未确认，相关测试应在对应决策完成后固定。

### 2.2 Provider 测试

Provider 应该通过协议或测试替身注入数据，不依赖测试机当时的真实电池和网络状态。

覆盖：

- BatteryProvider 能识别有内置电池和无内置电池。
- BatteryProvider 能识别电池、充电器和充电状态。
- NetworkProvider 能识别 Wi-Fi、有线网络、未连接。
- 无法确认热点时不会根据 SSID 名称猜测。
- Wi-Fi 名称或 RSSI 读取失败时只降级对应字段。
- HealthProvider 能处理 CPU、负载和热状态读取失败。
- 一个 Provider 失败不会阻断其他 Provider。
- NetworkControlProviding 的扫描、连接、记忆选项和 Wi-Fi 开关可通过测试替身验证。
- PowerPolicyProvider 和 PowerHelperClient 在未安装、待授权、已授权和后端不可用时返回正确能力状态。
- PowerPolicyProvider 在 helper 已授权时使用 active mode 读回，在 helper 不可用时保持安全的只读状态。

### 2.3 状态源测试

覆盖：

- SystemStatusStore 启动所有必要的刷新任务。
- 事件更新会更新统一快照。
- CPU 和负载按照固定周期刷新。
- 状态提交发生在 MainActor。
- 睡眠或读取失败时能标记数据不可用。
- 新快照会覆盖过期快照。
- 面板打开不会创建第二套轮询任务。

### 2.4 配置测试

覆盖：

- 健康指标可以保存和恢复。
- 开机启动选项可以保存和恢复。
- 图标外观可以保存和恢复。
- 默认折叠状态可以保存和恢复。
- 弹出面板修改健康指标后，设置面板读到相同值。
- 不保存 Wi-Fi 密码或管理员密码。

### 2.5 UI 测试

覆盖：

- 应用启动后显示菜单栏入口，不强制打开复杂主窗口。
- 点击菜单栏图标可以打开弹出面板。
- 弹出面板底部可以打开独立设置面板。
- 上下文菜单可以打开设置和退出应用。
- 弹出面板包含 Battery、Network、System Health 区域。
- 三个区域可以折叠和展开。
- 设置面板包含 V1 已确认的四类设置。
- 状态摘要在菜单栏图标和弹出面板中保持一致。
- Wi-Fi 控制页能展示扫描网络、已知网络和不可用网络的降级状态。
- 密码输入使用安全控件；“记住此网络”可选且默认关闭。
- 电源控制页区分公开只读状态、授权状态和后端不可用状态。
- 电源控制页按 Battery/Power Adapter 作用域展示模式行，只显示设备支持的模式；读回未知时提供 Battery 系统设置回退。
- 不支持的写入能力不显示可用编辑控件。
- 简体中文和英文界面可以加载，其他语言回退英文。

## 3. 功能测试矩阵

### 3.1 电池

| 场景 | 预期 |
| --- | --- |
| 有内置电池、普通使用 | 显示电量弧线和普通单色 |
| 由电源适配器供电 | 电池进度颜色为绿色 |
| 低电量模式 | 电池进度颜色为黄色 |
| 未由适配器供电且电量低于 20% | 电池进度颜色为红色 |
| 无内置电池 | 显示中性不可用状态和无内置电池说明 |
| 电源信息暂不可用 | 不显示伪造的 100% 状态 |

### 3.2 能源模式

| 场景 | 预期 |
| --- | --- |
| helper 已授权且输出包含 `powermode`/High Power | 显示 Automatic、Low Power、High Power 三行 |
| 只有 `lowpowermode` | 只显示 Automatic 和 Low Power |
| helper 未安装或未授权 | 显示只读状态、授权入口和 Battery 系统设置回退 |
| `pmset` 输出缺失或无法解析 | 显示暂不可用，不显示 Automatic，不执行写入 |
| 写入后读回不一致 | 保持未确认状态，不显示成功 |

### 3.3 网络

| 场景 | 预期 |
| --- | --- |
| Wi-Fi 已连接 | 显示 Wi-Fi、网络名称和可用信号级别 |
| 有线网络已连接 | 显示有线网络，不显示 Wi-Fi 信号强度 |
| 已确认个人热点 | 显示热点标签，不显示普通 Wi-Fi 信号强度 |
| 无法确认个人热点 | 显示普通 Wi-Fi，不根据 SSID 猜测 |
| 未连接 | 显示未连接，不显示网络名称和信号强度 |
| SSID 不可读 | 保留连接状态，SSID 显示暂不可用 |
| RSSI 不可读 | 保留连接状态和网络名称，信号显示暂不可用 |

Wi-Fi 控制需要在受控测试网络上验证；不在开发机上随意切换网络或提交系统配置。

### 3.4 系统健康

| 指标 | 预期 |
| --- | --- |
| CPU 使用率较低 | 健康点较多 |
| CPU 使用率较高 | 健康点较少 |
| 1 分钟负载较低 | 健康点较多 |
| 1 分钟负载较高 | 健康点较少 |
| Nominal | 健康分数 1.00 |
| Fair | 健康分数 0.67 |
| Serious | 健康分数 0.33 |
| Critical | 健康分数 0 |
| CPU 或负载短时抖动 | 图标不应明显闪烁 |
| 健康指标切换 | 菜单栏图标、弹出面板和设置面板同步 |

## 4. 兼容性矩阵

| 项目 | 当前要求 |
| --- | --- |
| macOS | 13 及更高版本 |
| 芯片 | 优先支持 Apple silicon |
| Intel | 不属于支持范围 |
| 网络 | Wi-Fi、有线网络、未连接；热点仅在系统确认时标记 |
| 权限 | 主应用不以 root 运行；电源辅助进程按需签名和授权 |
| 数据来源 | 本机 Apple 公开 API；能源模式由 helper 固定参数读取 `/usr/bin/pmset` |

兼容性验证需要完整 Xcode 和对应 SDK。当前工程已使用 Xcode 27 在 macOS destination 上通过应用构建和 `build-for-testing` 编译验证，单元测试也已在完整 Xcode 的 macOS destination 上执行通过。受限沙箱内直接连接 Xcode 的 `testmanagerd`/CoreSimulator 服务仍不可用；真实 Provider 仍需在 Apple silicon 设备上完成硬件状态验证。

本机执行完整 UI test target 时，UI runner 在建立连接前被系统以 `signal kill` 终止，未进入任何 UI 用例；因此该结果不作为断言失败处理，菜单栏和弹出面板仍需在可用的 UI runner 或实际设备上完成手动验收。

## 5. 手动验收顺序

1. 在 Apple silicon Mac 上启动应用。
2. 确认应用只在菜单栏提供入口。
3. 打开弹出面板，检查三个状态区域。
4. 分别验证电池、Wi-Fi、有线网络和未连接状态。
5. 切换 CPU、温度和负载指标。
6. 观察 CPU 和负载短时变化，确认图标不会明显闪烁。
7. 修改四类 V1 设置，重启应用后确认设置保留。
8. 切换系统语言，确认简体中文、英文和英文回退。
9. 检查能源模式的作用域、只读值、能力状态和辅助进程授权状态。
10. 仅在明确批准且使用专用测试设备时，验证 Wi-Fi 写入和电源模式写入；否则保持只读检查。

## 6. 验收限制

以下测试不能只依赖单台开发机：

- 无内置电池的 Mac。
- 有线网络。
- 个人热点身份被系统确认的场景。
- 各种系统热状态。
- 睡眠和唤醒。
- macOS 13 及更高版本之间的 API 差异。

无法复现的硬件状态必须通过 Provider 测试替身覆盖，不应为了测试而伪造系统级状态。

## 7. 合并控制版本验收

- Wi-Fi 关闭时仍可展示系统已知网络，并将不可连接项置为不可用；不猜测个人热点身份。
- Wi-Fi 连接操作显示 pending，成功条件是连接状态和目标 SSID 读回一致。
- 未勾选“记住此网络”时不主动提交配置文件；勾选后提交失败不能伪造 `wasRemembered=true`。
- 支持开放、WEP/dynamic WEP、WPA/WPA2/WPA3 personal、OWE 以及 enterprise 安全族；无法映射的安全类型明确失败。
- Wi-Fi 控制失败后保留真实当前网络状态，并提供打开系统网络设置的回退入口。
- 电源策略先读取能力；未安装、待授权、不可用、输出无法解析或读回未确认时不显示成功。
- 电源辅助进程只通过固定 XPC 方法通信，主应用启动和只读状态不依赖其在线。
- 所有写入都遵循 pending → backend → readback → confirmed/writeUnconfirmed，不自动重试高风险写入。

电源写入后端当前可返回不支持/不可用，这是预期的安全降级状态，不视为测试失败；应验证界面和状态源没有伪造可用能力。
